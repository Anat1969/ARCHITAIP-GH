# בנייה מקצה לקצה

ענת פותחת ריפו ב-GitHub ובוחרת פרויקט ב-Supabase. כל השאר עליי, בלי לעצור לשאלות שאפשר להכריע לבד. המטרה: כמה שפחות אינטראקציות.

## עקרונות

- תמיד בעברית. בלי אייקונים או סמלים, גם לא בכפתורים (בלי וי, איקס או חיצים דקורטיביים).
- לא להעביר אליה צעדים, סיסמאות, מפתחות או הגדרות. התוצר הוא כתובת חיה ושורה אחת על מה השתנה.
- לשאול רק כשההחלטה בלתי הפיכה ואפשר לפרש אותה לשני כיוונים. אחרת להחליט, ולציין את ההנחה בשורה אחת.
- כל חריגה מהסקיל הזה נאמרת מראש, לפני הבנייה, ולא בדיעבד.
- כשמשהו נחסם: לנסות כל דרך זמינה (כלי אחר, נתיב אחר) לפני שמדווחים. אם באמת אי אפשר, משפט אחד, בלי רשימת משימות בשבילה.
- לא לחזור על הערה שכבר נתנה. לפני כל בנייה לקרוא את CLAUDE.md בריפו. אחרי כל תיקון שלה, להוסיף אותו ל-CLAUDE.md.
- כל גרסה מקורית וחדשנית יותר מהקודמת. לא להעתיק תבניות.

## תהליך

1. **אפיון קצר בתוך התשובה**: בעיה, משתמש, מסלול מרכזי, מידע נשמר, מוצר מינימלי. לא לחכות לאישור אם הבקשה ברורה.
2. **מקור קיים**: כשענת מדביקה קובץ HTML גדול, לפצל ל-index.html, CSS, נתונים ולוגיקה, ולחלץ תמונות base64 לקבצים ב-public. לשמור על התוכן והלוגיקה, ולהוסיף את שפת העיצוב כשכבה מעל.
3. **חלופות עיצוב**: כשמבקשים לראות כיוונים, שלוש חלופות שונות באמת על קנבס Design, דף בית ודף פנימי לכל אחת.
4. **Supabase**: רק כשיש מידע לשמור. בפרויקט שבחרה. אם הפרויקט משותף, קידומת לכל הטבלאות והדלי. RLS תמיד: קריאה ציבורית למה שפורסם, כתיבה לאדמין בלבד. אדמין לפי user_id או email בטבלת admins.
5. **עריכה בלי חלונות**: ענת עורכת מכל מקום, בלי חלון כניסה, בלי מייל ובלי סיסמה. ברירת המחדל: **קישור עורכת אישי** (`#editor=...`) שנפתח פעם אחת בכל מכשיר ונשמר בו, והשרת שומר רק hash. כל כתיבה עוברת דרך Edge Function שבודקת את המפתח וכותבת עם service role. לעולם לא לפתוח חלון בתגובה לפעולה (הדבקה, גרירה, הקלדה): הפעולה מתבצעת מיד, ואם המכשיר עוד לא מזוהה מופיעה שורה שקטה בסרגל העליון. בסוף כל בנייה למסור את קישור העורכת.
   - לא להשתמש בכניסה במייל בפרויקט Supabase משותף: ה-Site URL שייך לאפליקציה אחרת והקישור חוזר לשם.
   - Google רק אם הוא מופעל ב-`/auth/v1/settings`. אחרת לא מציגים כפתור.
6. **קוד**: Vite + React + framer-motion (או Vite בלבד לאתר תוכן סטטי, ולומר זאת מראש). עברית ו-RTL. עריכה מתוך הדף עצמו (פס עריכה צף לאדמין).
7. **רכיבים קבועים בכל אפליקציה**:
   - **לוגו הסטודיו בכל אפליקציה**: בפינה הימנית של הסרגל העליון, מונוגרמה "A&I" ומתחתיה "אד' ענת שטיבלמן". לידו, אחרי קו מפריד, אייקון האפליקציה ושמה.
   - **הכפתורים מתחת ללוגו**: הסרגל העליון בנוי משתי קומות. למעלה הלוגו ושם האפליקציה, ומתחתם שורה אחת של כל הכפתורים והניווט, מיושרת לימין מתחת ללוגו. בנייד: קומה אחת וכפתור "תפריט".
   - סרגל ניווט עליון קבוע בכל הדפים, גם בעמודים פנימיים ובחלונות העמקה (הם נפתחים מתחתיו, לא מעליו).
   - שם האפליקציה הוא קישור לדף הבית. יש דף בית אמיתי שממפה את התוכן.
   - בסרגל העליון: "העתקת קישור" שמעתיק את המצב הנוכחי (נושא ותת־נושא בכתובת), כפתור "שיחת הפיתוח" לקישור השיחה שבה נבנתה האפליקציה, וכפתור "פרויקט המחקר" כשענת נותנת קישור לפרויקט Claude.
   - אפליקציה ניתנת להתקנה מ-Chrome: manifest, sw.js (דף מהרשת, תמונות ונכסים מהמטמון), אייקון בלי טקסט, וכפתור "התקנת האפליקציה" שמופיע כש-Chrome מציע התקנה. כך היא נפתחת בחלון Chrome משלה ולא בדפדפן הפנימי של Claude.
   - **תמונות**: בכל מקום שיש פרומפט יש מסגרת שמקבלת תמונה בגרירה (גם מלשונית אחרת), בהדבקה ב-Ctrl+V על המסגרת שמתחת לעכבר, בלחיצה לבחירת קובץ ובהדבקת קישור. גם בתצוגה המוגדלת. הכפתורים גלויים תמיד. תמונה מוקטנת לפני העלאה.
   - **PDF**: ההדפסה היא רכיב נפרד בגודל דף A4 אחד במילימטרים, תמונות כ-`<img>` (רקעים לא מודפסים), כל טקסט חתוך במספר שורות, שורות התמונה ממלאות את מה שנשאר. בבדיקה: כל עמוד מודפס יוצא בדיוק דף אחד.
8. **בדיקה**: Playwright מול `vite preview`, עם מוקים לכל קריאות Supabase וסשן אדמין מזויף. ללחוץ על כל כפתור, כל לשונית וכל פריט, ולוודא את הבקשה שנשלחת. בנייד: בלי גלילה אופקית. לוודא ב-DevTools שאין שגיאות התקנה (`Page.getInstallabilityErrors`). לצלם מסך ולהסתכל עליו.
9. **GitHub**: קומיט ודחיפה. אם הסביבה מחייבת ענף עבודה, PR ומיזוג מיד אחרי בדיקה ירוקה, בלי לשאול. ענת אישרה מיזוג קבוע.
10. **Vercel**: `create_project` עם `gitRepository` ובלי `teamId` (קריאות עם teamId נחסמות ב-403). `ssoProtection: null` כדי שהאתר יהיה ציבורי. ענף הייצור הוא main: רק מיזוג ל-main מעדכן את הכתובת הראשית.
11. **אימות**: לבדוק שהפריסה READY על main, ושהנתונים הציבוריים חוזרים מ-Supabase.
12. **מסירה**: כתובת סופית ושורה על מה נבנה. לעדכן CLAUDE.md בריפו.

## שפת עיצוב קבועה

- תמיד: הנפשות, עומק, צל, פרספקטיבות, גרדיאנטים ושכבות. אף פעם לא שטוח.
- ברירת מחדל: אדריכלי, מינימליסטי, גווני אפור, פונטים דקים בגדלים גדולים (IBM Plex Sans Hebrew), תוויות במונוספייס (IBM Plex Mono).
- צבעים שנושאים משמעות (קטגוריות, ממלכות) נשמרים, ולא מוחלפים באפור.
- בלי אייקונים.
- נגישות: טקסט רץ בניגודיות 4.5:1, משקל דק רק בכותרות גדולות.

## מלכודות ידועות

- הסביבה לא מגיעה ל-supabase.co ול-vercel.app: נתונים דרך כלי ה-SQL, אימות פריסה דרך כלי Vercel, מדיה ראשונית בתיקיית public.
- גלילה אופקית ב-RTL: לתת ל-grid העליון `grid-template-columns:minmax(0,1fr)` ו-`min-width:0` לשורות כפתורים. עטיפות motion בתוך שורת flex צריכות `flex: 0 0 auto`.
- פריט grid עם `overflow:hidden` בתוך מיכל גלילה מתכווץ לגובה אפס. במיכל כזה: `grid-auto-rows:max-content`.
- הפעלת GitHub Pages חסומה דרך ה-API. Vercel הוא ברירת המחדל.
- קידום פריסת preview לייצור ב-Vercel נכשל (422). הדרך לעדכן את הכתובת הראשית היא מיזוג ל-main.
- מנגנון ההרשאות של Claude Code עלול לחסום מיזוג עד שענת כותבת "מזג" במפורש. בפרויקט עם CLAUDE.md שמתעד אישור קבוע, למזג.
